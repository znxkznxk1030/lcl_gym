# 크로스도킹 MARL 시뮬레이터 — Domain Randomization 기반 강인성 개선

---

## 1. 문제 정의 & 세팅 + 시나리오

### 1.1 배경: 크로스도킹(Cross-Docking)

크로스도킹은 입고된 화물을 창고에 보관하지 않고, 도착 즉시 목적지별 레인으로 분류하여 출고하는 물류 운영 방식이다. 본 프로젝트는 이러한 크로스도크 터미널의 자원 배정(도어/도크 스케줄링) 문제를 **다중 에이전트 강화학습(MARL)** 환경으로 모델링하고, 규칙 기반·최적화·학습 기반 정책의 성능을 비교한다.

### 1.2 환경 구조 (2-Stage)

인바운드 트럭은 3개의 인바운드 도어를 통해 하역된 뒤, 목적지별로 5개의 레인 큐(에이전트)로 분류되고, 다시 3개의 아웃바운드 도크를 통해 최종 출발한다.

> (※ 전체 흐름도 이미지로 대체 예정)

| 구성 요소 | 설명 |
|---|---|
| Lane (5개, 에이전트) | 목적지별 레인. 각 레인이 독립적인 강화학습 에이전트 |
| InboundDoor (3개) | 트럭 하역 전용. 하역 1~10스텝, **도어 고장 돌발사항** 발생 가능 |
| Buffer | 하역 완료 화물이 레인으로 분류되기 전 거치는 공간 (실험 설정상 overflow는 거의 발생하지 않는 비제약 조건) |
| OutboundDoor (3개) | 도크 5개 < 레인 5개 → **도크 희소성** 구조. 최대 15 CBM, 12~28스텝 후 출발 |

**Tick(틱)**은 본 시뮬레이터의 최소 시간 단위로, 모든 에이전트가 동시에 행동을 1회 수행하는 한 스텝(step)에 해당한다. 예를 들어 인바운드 하역에 1~10틱, 아웃바운드 적재 후 출발까지 12~28틱이 소요되는 식으로 환경 내 모든 시간 파라미터는 틱 단위로 정의된다.

에피소드는 50~70대의 트럭(2~3개 목적지 화물 혼재)이 도착해 모든 화물이 출발할 때까지 진행되며, 에피소드 종료까지 누적된 틱 수, 즉 **총 소요 시간(Total Ticks)** 을 최소화하는 것이 목표다. Total Ticks가 낮을수록 동일한 화물량을 더 빠르게 처리했음을 의미한다.

### 1.3 본 리포트의 핵심 시나리오

돌발사항이 전혀 없는 정적인 환경에서는 MILP나 GA 같은 고전적 방법만으로도 RL과 거의 동등하거나 오히려 더 나은 성능을 낼 수 있었다. 즉, 환경이 매번 동일한 규칙으로만 돌아간다면 굳이 학습 기반 정책이 필요하지 않을 수도 있다.

그러나 실제 물류 현장은 도어 고장과 같은 예측 불가능한 돌발 상황이 상시 존재하며, 이런 동적인 환경에서는 고정된 최적화 결과(MILP)나 진화된 규칙(GA)이 상황 변화에 맞춰 행동을 바꾸지 못한다는 한계가 있다. RL은 관측을 통해 현재 상황(예: 유휴 도어 수 감소)을 감지하고 행동을 적응적으로 바꿀 수 있다는 점에서, 바로 이 돌발 상황 대응이야말로 RL을 도입해야 하는 핵심 근거가 된다.

환경에는 인바운드 도어 고장이라는 돌발사항이 모델링되어 있으며, 일정 확률로 발생하면 도어 1개가 10~20틱 동안 비가동 상태가 된다. 평소에는 낮은 확률로 가끔 발생하던 도어 고장이, 특정 시기에는 훨씬 자주 발생할 수도 있다 — 즉 학습 당시 가정했던 돌발 발생 빈도와 실제 운영 중 마주치는 빈도가 달라질 수 있다는 것이다. 본 리포트는 이러한 상황에서 학습된 RL 정책이 베이스라인 정책들에 비해 얼마나 안정적으로 작동하는지를 살펴본다.

## 2. 알고리즘 상세 설명을 포함한 풀이 과정

제안한 모델은 **IQL(Independent Q-Learning) 기반 강화학습**을 사용한다. 5개 레인 에이전트가 하나의 Q-network 가중치를 공유하되, 행동을 결정할 때는 각자 자신의 관측만을 입력으로 사용해 독립적으로 의사결정을 내리는 구조다.

### 2.1 비교 대상 정책 개요

| 정책 | 핵심 로직 |
|---|---|
| Random | 매 스텝 일정 확률로 무작위 행동을 선택하는 정책 |
| FIFO | 대기 중인 트럭을 도착한 순서대로 가장 먼저 처리하는 정책 |
| Greedy | 매 순간 가장 시급해 보이는 레인(화물이 쌓여 있고 도크가 비어 있는 레인)을 우선적으로 처리하는 정책 |
| Heuristic | 내 레인에 화물은 있는데 배정된 도크가 비어 있으면 도크를 재배정받고, 버퍼가 일정 수준 이상 차 있으면 인바운드 요청을 자제하며, 그 외에는 긴급도·매칭도·혼잡도를 종합한 점수가 임계값을 넘을 때만 트럭을 받아들이는 규칙 기반 정책 |
| MILP | 매 스텝, 대기 중인 트럭과 비어 있는 도어의 모든 조합에 대해 화물의 긴급도(출발까지 남은 시간이 적을수록 높은 가중치)를 반영한 점수를 계산하고, 이 점수의 합이 최대가 되도록 트럭-도어 배정을 최적화하는 정책. CBC 솔버로 매 스텝 최적해를 구함 |
| GA (7-gene) | 긴급도, 목적지 일치도, 혼잡도, 버퍼 여유, 대기 시간 등 여러 요소에 가중치를 곱해 합산한 점수를 계산하고, 이 점수가 임계값을 넘으면 인바운드 트럭을 받아들이는 정책. 가중치와 임계값은 유전 알고리즘으로 탐색 |
| RL (IQL+DQN) | 5개 레인이 가중치를 공유하는 2층 MLP 기반 Q-network |

### 2.2 본 리포트 핵심 기여 — IQL 기반 강화학습 (IQL + Parameter Sharing DQN)

#### Action / State / Reward 설계

**Action (3-action, 이산 행동공간)**

| 행동 | 내용 |
|---|---|
| 0 (skip) | 아무 행동도 하지 않음 |
| 1 (인바운드 요청) | 유휴 도어에 대기 트럭 배정을 요청 |
| 2 (아웃바운드 도크 우선/재배정 요청) | 내 레인에 도크를 우선 배정하거나, 빈 레인을 서비스 중인 도크를 재배정받음 |

**State (관측, 12차원)**

대기 중인 개별 트럭의 화물 구성이나 모든 도어·도크의 상세 상태를 그대로 입력하면 상태 공간이 트럭·도어 수에 따라 가변적이고 지나치게 커져 학습이 어렵다. 따라서 이러한 정보를 레인 에이전트 입장에서 의미 있는 통계량(큐 화물량, 혼잡도, 매칭 점수 등)으로 압축·요약하여 고정 길이의 12차원 벡터로 표현했다. 레인 에이전트 $k$의 관측 벡터는 다음과 같이 정의된다.

$$s_k = \big[\, q_k,\ c_k,\ f_k,\ \tau_k,\ b,\ d_{\text{idle}},\ n_{\text{wait}},\ o_{\text{idle}},\ m_{k,1}, m_{k,2}, m_{k,3} \,\big] \in \mathbb{R}^{12}$$

| 구분 | 변수 | 내용 |
|---|---|---|
| 레인 상태 | $q_k$ | 내 레인 큐 화물량 |
| | $c_k$ | 레인 혼잡도 |
| 도크 상태 | $f_k$ | 내 레인에 배정된 아웃바운드 도크의 탑재율 |
| | $\tau_k$ | 출발까지 남은 타이머 |
| 버퍼 상태 | $b$ | 정렬 버퍼 충전율 |
| 자원 가용성 | $d_{\text{idle}}$ | 유휴 인바운드 도어 수 |
| | $o_{\text{idle}}$ | 유휴 아웃바운드 도크 수 |
| | $n_{\text{wait}}$ | 대기 중인 트럭 수 |
| 매칭 정보 | $m_{k,1..3}$ | 인바운드 도어별 매칭 점수 (내 레인 화물과의 일치도) |

**Reward**

레인 에이전트 $k$가 매 스텝 받는 보상은 모든 에이전트가 공유하는 환경 보상과, 에이전트 자신의 관측에 기반한 보상 셰이핑(shaping) 항의 합으로 정의된다.

$$R_k(t) = R_{\text{env}}(t) + R_{\text{shape},k}(t)$$

$$R_{\text{env}}(t) = -1.0 - 0.3 \times \text{overflow}(t)$$

$$R_{\text{shape},k}(t) = B^{\text{request}}_k(t) + B^{\text{boost}}_k(t) + P^{\text{buffer}}_k(t)$$

$R_{\text{env}}$은 매 스텝 -1의 시간 패널티로, 트럭이 한 대라도 빨리 처리되어 에피소드가 일찍 끝날수록 누적 패널티가 줄어들도록 유도한다. $R_{\text{shape},k}$의 각 항은 레인 $k$의 관측값($q_k, f_k, b, d_{\text{idle}}, n_{\text{wait}}$)과 선택한 행동에 따라 다음과 같이 결정된다.

| 항 | 발동 조건 | 행동에 따른 값 | 의미 |
|---|---|---|---|
| $B^{\text{boost}}_k$ | 내 레인에 화물이 쌓여 있는데 배정된 도크의 탑재율이 0인 경우 (도크 보강이 필요한 상황) | 행동=2: $+0.8$ / 그 외: $-0.5$ | 도크 재배정이 필요한 상황에서의 보너스/패널티 |
| $B^{\text{request}}_k$ | 유휴 인바운드 도어와 대기 트럭이 모두 존재하고, 정렬 버퍼에 여유가 있는 경우 | 행동=1: $+0.4$ / 그 외: $-0.3$ | 인바운드 요청이 가능한 상황에서의 보너스/패널티 |
| $P^{\text{buffer}}_k$ | 유휴 인바운드 도어와 대기 트럭이 모두 존재하지만, 정렬 버퍼가 과부하 상태인 경우 | 행동=1: $-1.0$ / 그 외: $0$ | 버퍼가 과부하인 상태에서 추가 인바운드를 요청하면 부과되는 패널티 |

세 조건은 서로 배타적이지 않게 동시에 평가되며, 해당하지 않는 항은 0으로 처리된다. 즉 한 스텝에서 도크 보강과 인바운드 요청 상황이 동시에 발생하면 두 보너스/패널티가 합산된다.

#### 네트워크 구조 및 학습 설정

```
입력(12) → Linear(64) → ReLU → Linear(3) → Q값 {Q_skip, Q_inbound, Q_outbound}
```

- **TD 타깃**: $y_i = r_i + \gamma \max_{a'} Q^-(\hat{s}_i', a')(1-d_i)$ — 실제 받은 보상 $r_i$에, 다음 상태에서 타깃 네트워크가 추정한 최대 미래 가치를 더해 "이 (상태, 행동)이 가졌어야 할 가치"를 근사한 값
- **손실**: $\mathcal{L} = \frac{1}{B}\sum (y_i - Q(\hat{s}_i,a_i))^2$ (선택 행동에만 역전파) — TD 타깃과 현재 네트워크의 예측값 차이(TD error)를 줄이는 방향으로 가중치를 업데이트
- **학습**: 2000 에피소드, lr=1e-3, γ=0.99, ε: 1.0→0.05, target sync 50ep마다, replay buffer 10,000
- **Reward Shaping**: 도크가 비어 있는데 화물이 있는 상황에서 action=2를 선택하면 보너스를 주는 등, 핵심 행동의 학습을 가속하는 보조 보상을 추가 (효과는 4장 ablation에서 검증)

5개의 독립적인 에이전트가 가중치를 공유함으로써, 한 레인에서의 경험이 즉시 다른 레인의 정책 개선에도 반영되어 학습 표본 효율이 높아진다는 점이 본 알고리즘의 핵심 설계 의도다.

### 3.2 RL vs 베이스라인 정책 비교

5개 레인이 가중치를 공유하는 IQL+DQN을 2000 에피소드 학습한 뒤, 다른 정책들과 함께 20 에피소드 벤치마크한 결과는 다음과 같다.

| 정책 | Avg Ticks ↓ | Std | 빈 출발 ↓ | 출발 횟수 |
|---|---:|---:|---:|---:|
| 🥇 **RL** | **339.1** | 11.9 | **2.70** | 48.80 |
| Random | 339.5 | 12.5 | 4.75 | 50.25 |
| MILP | 341.1 | 12.0 | 5.00 | 50.50 |
| FIFO | 341.6 | 12.4 | 4.85 | 50.50 |
| GA | 344.9 | 17.5 | 4.10 | 50.45 |
| Heuristic | 349.6 | 20.6 | 4.55 | 50.25 |
| Greedy | 350.9 | 17.1 | 4.50 | 50.45 |

> 모든 정책의 처리 화물량은 444.8 ± 56.8 CBM으로 동일하다(에피소드는 모든 화물 처리 후 종료). 즉 "동일한 화물을 얼마나 빠르게 처리하는가"가 비교 기준이며, RL이 가장 적은 Total Ticks와 가장 적은 빈 출발 횟수를 동시에 달성했다.

### 3.3 보상 셰이핑(Reward Shaping) Ablation 실험

2.2절에서 설계한 보상 중 보상 셰이핑(Reward Shaping)의 두 구성요소 — **인바운드 셰이핑**(유휴 도어·대기 트럭이 있을 때 action=1 유도)과 **아웃바운드 셰이핑**(도크 없이 화물이 있을 때 action=2 유도) — 을 각각 제거했을 때의 영향을 측정했다.

#### Variant 정의

| Variant | 인바운드 셰이핑 | 아웃바운드 셰이핑 | 설명 |
|---|:---:|:---:|---|
| **full** | ✓ | ✓ | 기준 (현재 설정) |
| **no_out** | ✓ | ✗ | action=2 유도 보상 제거 |
| **no_in** | ✗ | ✓ | action=1 유도 보상 제거 |
| **no_shaping** | ✗ | ✗ | 환경이 주는 기본 보상만 사용 |

#### 결과 (1000 에피소드 학습, 20 에피소드 벤치마크)

| Variant | Avg Ticks ↓ | Std | 빈 출발 ↓ | full 대비 |
|---|---:|---:|---:|---:|
| 🥇 **full** | **342.3** | 12.4 | 4.20 | — |
| no_in | 342.9 | 13.2 | **3.45** | +0.6 |
| no_out | 343.9 | 10.8 | 4.60 | +1.6 |
| no_shaping | 344.4 | 11.4 | 5.30 | +2.1 |

> 학습 에피소드 1000ep 기준(3.2절은 2000ep)이므로 절대 수치보다 **상대적 차이**가 핵심이다.

두 셰이핑 항 중 **아웃바운드 셰이핑(action=2 유도) 제거가 Total Ticks를 가장 크게 악화**시켰고(+1.6), 인바운드 셰이핑(action=1 유도) 제거는 Ticks에는 소폭(+0.6)의 영향만 주면서 오히려 빈 출발은 개선(4.20→3.45)되었다. 셰이핑을 전부 제거한 `no_shaping`은 Ticks·빈 출발 양쪽 모두에서 가장 나쁜 결과(+2.1, 5.30)를 보였다. 즉 두 셰이핑 항 모두 학습에 긍정적으로 기여하지만, 그 중에서도 아웃바운드 셰이핑이 RL이 베이스라인을 능가하는 핵심 행동(action=2를 통한 빈 출발 감소)을 학습시키는 데 더 결정적인 역할을 한다 — 자세한 메커니즘은 4.2절에서 다룬다.

## 4. 토의 (및 수학적 분석)

### 4.1 RL 우위가 성립하는 조건: 돌발 확률에 따른 3단계 비교

돌발사항(도어 고장) 발생 확률을 0%부터 점진적으로 높여가며 RL과 베이스라인을 비교하면, RL의 우위는 특정 구간에서만 성립하는 것을 확인할 수 있다.

| 환경 조건 | RL (Avg Ticks) | 최고 베이스라인 | 비교 |
|---|---:|---:|---|
| 돌발 없음 (확률 0%) | 339.2 | MILP 337.5 | RL이 근소하게 뒤짐 — 고전적 방법(MILP·FIFO)만으로도 충분 |
| 학습 조건 (확률 2%) | 339.1 | FIFO 341.6 | **RL이 최고** — action=2를 통한 적응적 재배정의 이점이 발현 |
| 학습 범위 밖 (확률 5% 이상) | 824.4 ~ 8084.1 | FIFO 342.6 ~ 491.0 | **RL 붕괴** — FIFO가 오히려 훨씬 안정적 |

돌발사항이 전혀 없는 정적인 환경에서는 도크와 화물의 배정 문제가 비교적 단순하여, 매 스텝 최적화를 수행하는 MILP나 단순한 FIFO만으로도 RL과 거의 동등한 성능을 낸다. 반면 학습 시 가정한 수준(2%)의 돌발사항이 존재하는 환경에서는, RL이 관측을 통해 "도어 고장으로 비게 된 도크"를 감지하고 즉시 재배정하는 적응적 행동을 학습해 베이스라인을 능가한다 — 이것이 1.3절에서 제시한, RL을 도입해야 하는 핵심 근거다.

그러나 돌발 확률이 학습 시 가정(2%)을 벗어나 5% 이상으로 높아지면, RL의 성능은 오히려 급격히 무너진다(Avg Ticks 339→824→1800→5670→8084). 이는 RL이 학습 중 거의 경험하지 못한 관측 분포(장기간 다수 도어 고장)에서 Q-network가 부적절한 행동을 반복하는 **분포 이탈(distribution shift)** 문제 때문이다. 반면 FIFO·Greedy 같은 규칙 기반 정책은 동일한 조건에서 완만하게만 성능이 저하된다(341→491, 약 44% 증가).

종합하면, RL의 우위는 "돌발사항이 존재하지만 학습 시 가정한 분포를 벗어나지 않는" 좁은 구간에서만 성립한다. 이는 RL이 단순히 베이스라인보다 항상 우수한 것이 아니라, **학습 조건과 일치하는 환경에서 적응적 행동을 통해 우위를 가지는 대신, 그 조건을 벗어나면 규칙 기반 정책보다도 취약해지는 트레이드오프**를 가진다는 것을 보여준다. 이 트레이드오프를 어떻게 완화할 것인지는 4.3절의 추후 과제로 남긴다.

### 4.2 보상 셰이핑(Reward Shaping) Ablation 분석

환경이 기본적으로 주는 보상(R_env)은 **출발이 발생하는 스텝에서만** 값을 가지는 희소 보상(sparse reward)이다. 그런데 action=2(도크 재배정)를 선택하는 시점과 그로 인한 화물 출발 시점 사이에는 도크의 적재~출발 타이머(12~28틱)만큼의 시간차가 존재한다. 할인율 γ=0.99를 적용하면, 20틱 뒤에 발생하는 보상이 현재 시점에 기여하는 가치는

$$\gamma^{20} = 0.99^{20} \approx 0.82$$

로, 보상 신호가 약 18% 감쇠된 채로 전달된다. 게다가 그 사이 다른 행동들의 TD 업데이트가 누적되므로, "지금 action=2를 선택한 것"과 "20틱 후 출발이 발생한 것" 사이의 **신용 할당(credit assignment)** 이 어렵다. 아웃바운드 셰이핑은 이 시간차를 제거하고 action=2 직후 즉시(+0.8/−0.5) 피드백을 주므로, 이 행동의 학습을 직접적으로 가속한다. 이것이 `no_out`(아웃바운드 셰이핑 제거) 시 Total Ticks가 +1.6으로 가장 크게 악화되는 이유다.

반면 인바운드 셰이핑(`no_in`)을 제거하면 Total Ticks는 소폭(+0.6) 악화되지만 빈 출발은 오히려 4.20→3.45로 개선된다. 이는 인바운드 셰이핑이 "유휴 도어·대기 트럭이 있으면 무조건 action=1"을 유도하는 과정에서, 특정 레인에 화물이 과도하게 쏠려 도크 배정 타이밍과 어긋나는 트레이드오프를 유발하기 때문으로 해석된다.

`no_shaping`(셰이핑 전체 제거)이 Ticks·빈 출발 양쪽 모두 최악인 것은, R_env만으로는 위에서 설명한 신용 할당 문제가 인바운드·아웃바운드 행동 모두에서 발생해 학습이 더디기 때문이다. 종합하면, **두 셰이핑 항 중 아웃바운드 셰이핑(도크 재배정 유도)이 action=2를 통한 적응적 재배정 행동을 학습시키는 데 더 결정적인 역할**을 한다고 결론지을 수 있다.

### 4.3 한계 및 추후 과제

| 한계 | 설명 |
|---|---|
| 보상 셰이핑 크기의 수동 설정 | 셰이핑 보너스 크기(+0.8/−0.5, +0.4/−0.3, −1.0 등)가 휴리스틱하게 결정됨 → 자동 탐색(예: 보너스 크기 자체를 GA로 탐색) 여지 |
| Ablation 학습 길이 차이 | 3.2절(2000ep)과 3.3절(1000ep)의 절대 수치가 직접 비교 불가능 → 동일 학습 길이에서의 재검증 필요 |
| 단일 시드 학습 | 보고된 결과는 단일 시드 학습 결과로, 학습 자체의 분산(seed variance)은 별도 검증되지 않음 |
| 돌발 환경에서의 일반화 | 본 ablation은 돌발 확률 2% 고정 조건에서만 수행됨. 1.3절에서 제기한 "학습 시 가정과 다른 돌발 빈도"에서도 동일한 보상 설계가 유효한지는 별도 검증이 필요한 추후 과제 |
| RL의 분포 이탈(distribution shift) | 4.1절에서 확인한 것처럼, 학습 시 가정한 돌발 확률(2%)을 벗어나면 RL 성능이 급격히 붕괴함. 다양한 돌발 확률을 학습에 포함시키는 등의 재학습 전략으로 완화 가능할 것으로 예상되나 본 리포트에서는 검증하지 못함 |

### 4.4 정책별 복잡도 분석

| 정책 | 스텝당 시간복잡도 | 비고 |
|---|---|---|
| Random / FIFO / Greedy / Heuristic | $O(L)$ | $L$=레인 수(5), 단순 조건 분기 |
| GA | $O(L)$ | 7개 선형 가중치 내적, 추론 비용은 규칙 기반과 동일 |
| RL (IQL+DQN) | $O(L \cdot (d \cdot h + h \cdot 3))$ | $d$=관측 차원(12), $h$=은닉 유닛(64) → 레인당 약 $12{\times}64+64{\times}3 \approx 960$ FLOPs |
| MILP | 매 스텝 CBC 솔버 호출, 평균 ~9ms/스텝 | 트럭×도어 이분 매칭 — 가장 높은 연산 비용 |

RL의 시간복잡도 $O(L \cdot (d \cdot h + h \cdot 3))$에서 $L$(레인 수), $d$(관측 차원), $h$(은닉 유닛 수)는 모두 트럭·도어 수와 무관한 고정값이므로, 추론 비용은 매 스텝 동일한 크기의 행렬 연산(레인당 약 960 FLOPs)으로 일정하다. 반면 MILP는 매 스텝 대기 트럭×도어 조합에 대한 최적화 문제를 풀어야 하므로 트럭·도어 수가 늘어날수록 솔버 호출 비용이 증가한다. 따라서 RL은 GA·규칙 기반과 마찬가지로 입력 규모에 따라 비용이 늘어나지 않는 고정 비용 연산이라는 점에서 실시간 배포에 적합하며, MILP 대비 약 1000배 이상 빠르다(밀리초 미만 vs ~9ms). 본 리포트의 핵심은 정확도(ticks) 측면에서 RL이 MILP·GA 등 고전적 방법과 동등하거나 더 나은 성능을, 훨씬 적은 연산 비용으로 달성한다는 점이다.

## 5. 개인 기여도

본인은 팀 프로젝트에서 크로스도킹 환경에 강화학습을 적용한다는 연구 방향을 제안하고, 이를 구현·검증하는 과정 전반에 참여했다. 먼저 트럭이 인바운드 도어를 통해 들어와 정렬 버퍼를 거쳐 5개 레인으로 분류되고 아웃바운드 도크를 통해 출발하는 2-Stage 크로스도킹 구조를 시뮬레이션 환경으로 구현했다. 이 환경 위에서 각 레인을 담당하는 에이전트가 현재 상황을 보고 어떤 행동을 할지 선택하도록 행동·관측·보상을 설계하고, 이를 학습할 강화학습 모델을 적용했다.

이렇게 만든 환경과 모델을 바탕으로, 규칙 기반 정책(FIFO, Greedy 등)이나 최적화 기반 정책(MILP, 유전 알고리즘)과 동일한 조건에서 성능을 비교하는 실험을 수행했다. 또한 보상 설계 중 일부 요소를 제거했을 때 학습 결과가 어떻게 달라지는지를 비교하는 실험과, 도어 고장과 같은 돌발 상황의 발생 빈도를 점차 높여가며 학습된 정책이 어떻게 반응하는지를 살펴보는 실험을 설계·실행하고, 그 결과를 분석했다.

### B. 평가(S/W Tool 기반 정량 평가) 방법론

- **도구**: 본 환경(`CrossDockEnv`, numpy 기반 자체 시뮬레이터)을 S/W tool로 사용하여 정책별 에피소드를 실행하고 `env.metrics`(total_ticks, empty_departures, disruption_door_failures 등)를 자동 집계
- **표본**: 레벨당 20 에피소드(seed 0~19), 평균(mean)·표준편차(std) 산출
- **재현성**: 모든 실험은 고정 seed로 실행되어 동일 트럭 도착 스케줄·고장 발생 시점에서 정책 간 비교가 가능
